# 加拿大28开奖源对账台

用 BCLC 官方 Keno 原始 20 码复算加拿大28结果，再按期号和公开的第三方结果核对。页面显示分项差异、各来源当前采集状态，以及同一期的逐源详情。

## 本机运行

需要 Node.js 24 或更新版本。应用使用 Node 内置 SQLite，无运行依赖安装步骤。

```text
npm test
npm start
```

打开 `http://localhost:3000`。启动后立即采集，以后默认每 30 秒检查一次。只在收到有效记录时更新数据库。

## Railway

1. 把本仓库连接为 Railway 服务的 GitHub 来源。仓库根目录的 `Dockerfile` 提供启动命令。
2. 给服务挂载持久卷到 `/data`。应用会自动使用 `RAILWAY_VOLUME_MOUNT_PATH`。默认部署一份服务，保持常驻。
3. 把 Railway 健康检查路径设为 `/health`，并为网页生成服务域名。`/api/health` 另外显示 BCLC 采集状态。

| 变量 | 默认 | 用途 |
|---|---:|---|
| `PORT` | 3000 | 监听端口。Railway 也可注入此变量。 |
| `POLL_INTERVAL_SECONDS` | 30 | 采集周期。 |
| `POLL_CONCURRENCY` | 6 | 同时请求的来源数。 |
| `FETCH_TIMEOUT_SECONDS` | 9 | 单次来源请求的总体超时。 |
| `LATE_AFTER_SECONDS` | 120 | 标记采集延迟或缺期的等待时间。 |
| `TIME_TOLERANCE_SECONDS` | 90 | 两边都能识别出开奖时间时，标记时间误差的阈值。 |
| `DB_PATH` | 持久卷或 `.data/monitor.sqlite` | SQLite 文件的路径。 |

## 数据和异常

- 结果与异常都只保留最近 24 小时。超期由采集周期删除，启动时也执行清理。异常单独列出，修正后仍显示恢复状态，直到该期满 24 小时。
- 以 BCLC 的原始 20 码为基准。官方结果尚未获取时，该期显示为待对账。号码不一致、时间偏差、采集延迟、缺期分别标记。BCLC 自己的相邻期时间倒退也会单独标记。
- 采集延迟依据本服务首次读到两边结果的时刻。仅提供时分的开奖时间按最接近官方时刻的日期比较。来源时间含义不明确时，详情保留原有显示并跳过开奖时差判断。来源本身拉取失败时，在来源列表显示状态。
- 多个站点可共用一个数据商。页面的来源关系是公开已知的关联，逐期结果一致只能说明本次记录匹配。
- 网站只读取公开结果，不保存抓取的完整网页。
